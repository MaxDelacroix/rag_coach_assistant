**на разработку RAG‑ассистента для работы с документами (система вопрос‑ответ по базе знаний)**

### 1. Описание проекта

#### 1.1. Цель проекта
Создание интеллектуального веб‑приложения (RAG‑ассистента), которое позволяет пользователям задавать вопросы на естественном языке и получать точные ответы с цитированием источников из предоставленной библиотеки документов (книг, инструкций, методических материалов). Система особенно полезна для организаций, обладающих большим объёмом текстовой информации (тренерские штабы, учебные центры, консалтинговые фирмы, юридические и медицинские отделы).

#### 1.2. Используемые технологии
- **Backend:** Python, FastAPI, Uvicorn  
- **AI:** OpenAI API (модели `text-embedding-3-small`, `gpt-5` или аналоги)  
- **Векторная БД:** ChromaDB (локальное развёртывание)  
- **Обработка документов:** собственный модульный pipeline (парсеры docx / pdf / txt / изображения, PreChunk‑структурирование, контролируемый чанкинг, постобработка)  
- **OCR:** PaddleOCR (для сканированных PDF и изображений)  
- **Фронтенд:** HTML / CSS / JavaScript (лёгкое веб‑приложение)  
- **Деплой:** Ubuntu VPS, Nginx (возможна установка на инфраструктуре заказчика)

#### 1.3. Среда для разворачивания
- Облачный сервер (VPS) под управлением Linux (рекомендуется 4 vCPU, 8 ГБ RAM, 50 ГБ SSD)  
- Доступ к OpenAI API (или возможность использования локальной LLM)  
- Установка системы внутри контура заказчика (on‑premise) — по требованию

### 2. Основные функции

#### 2.1. Функциональные требования

##### 2.1.1. Основные функции (для конечного пользователя)
- **Выбор источников:** пользователь может выбрать одну, несколько или все загруженные в систему книги / документы для поиска.  
- **Свободный вопрос:** ввод текстового вопроса на русском (или другом языке) в веб‑интерфейсе.  
- **Поиск по смыслу:** система находит релевантные фрагменты документов с помощью векторного поиска.  
- **Формирование ответа:** LLM генерирует ответ **исключительно на основе найденных фрагментов**, без выдумывания фактов.  
- **Цитирование:** каждый ответ сопровождается ссылками на конкретные документы, разделы и страницы.  
- **Настройка точности:** возможность регулировать количество возвращаемых фрагментов (`top_k`).  
- **Прозрачность:** отображение исходных фрагментов, на которых основан ответ.

##### 2.1.2. Административные функции
- **Загрузка новых документов** через веб‑интерфейс или CLI‑скрипты.  
- **Поддержка форматов:** DOCX, TXT, PDF (векторные + сканы с OCR), изображения (через OCR).  
- **Управление библиотекой:** просмотр списка книг, их удаление, обновление метаданных.  
- **Контроль доступа:** защита системы по коду (X‑Access‑Code).  
- **Логирование и мониторинг:** просмотр запросов, ошибок, времени ответа.

#### 2.2. Ключевые технические детали

##### 2.2.1. Архитектура
Система построена по модульному принципу **ETL + RAG**:
1. **Pipeline обработки документов:**  
   - Парсинг → PreChunk (восстановление структуры глав, разделов, пунктов) → Контролируемый чанкинг (с перекрытием) → Постобработка (обогащение метаданными) → Создание эмбеддингов → Загрузка в векторную БД.  
2. **Сервис поиска и генерации:**  
   - FastAPI‑эндпоинты → ChromaDB (фильтрация по выбранным книгам) → LLM (формулировка ответа с цитатами).  
3. **Веб‑интерфейс:** статический HTML/JS, общается с API.

##### 2.2.2. Структура базы данных (векторное хранилище)
- **Коллекция:** `rag_books_v1`  
- **Каждый чанк хранит:**  
  - `text` — текст фрагмента  
  - `metadata` — doc_id, document_title, source, page_start, page_end, section_title, and any custom fields  
- **Реестр книг:** JSON‑файл `books_registry.json` со списком doc_id, названий, авторов, даты добавления.

### Почему стоит выбрать наше решение?

- ✅ **Уникальный pipeline PreChunk** — сохраняет структуру документа (главы, разделы, списки), что повышает точность ответов.
